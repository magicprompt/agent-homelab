agent-homelab

Build your own
always-on
AI agent.

A lightweight guide to self-hosting an agent on hardware you control — what's required, what's optional, and why it's worth doing.

01 · Why

A cloud chatbot answers.
A cloud sandbox is
someone else's box.

A self-hosted agent runs on hardware you control, with real access to your own files, tools, and network — not a hermetically sealed service you're renting by the message.

02 · The shape

Three things.
That's it.

01
A machine that's always on
02
Open agent software running on it
03
A way to reach it from anywhere

Everything else in this guide is optional detail layered on top.

03 · Hardware

Always on
beats powerful.

Any machine that can stay powered on 24/7 works — a spare Mac mini, an old laptop, a NUC, a small home server. Turn it off and the agent is gone, unless it's running in the cloud.

Required
A machine you leave running
Optional
A small UPS (battery backup) so a power blip doesn't take it down mid-task

04 · Remote access

Pick your depth.

  • Tier 1 — SSH + multiplexerTerminal access that survives disconnects. Reattach from any device, including your phone.
  • Tier 2 — Remote desktopFull screen control over your private network when a task needs a GUI.
  • Tier 3 — Hardware KVMPhysical keyboard, video, and power control. Recovers you even from a crash or a bad reboot that SSH can't reach.

Most people only need tier one or two. Tier three is for when you've been burned once.

05 · Network

A private mesh,
not open ports.

From outside the mesh, the machine doesn't exist. No forwarded ports, no public endpoint.

06 · Daily access

Same agent,
any door.

Phone
A messaging app bot — quick asks from anywhere
Desk
Desktop app or terminal — deeper work sessions
Scripts
An API endpoint on the mesh — other tools can call it too

One session store, one memory, whichever door you walk through.

07 · Bonus capability

Run coding agents
on your own box.

SSH into your always-on machine and run Claude Code, Codex, or any coding agent directly on it. Kick off a task, disconnect, check back in later from your phone.

Why it's better
Your dotfiles, your packages, your disk — not a sealed cloud sandbox
Needs
SSH + a terminal multiplexer so sessions survive disconnects

08 · Local models

A second machine,
open models.

An old laptop on the same mesh can run an open-model server and serve local inference. No API key, nothing leaves your network.

Use case
Fallback when cloud providers are down
Use case
Genuinely private for sensitive work

09 · Privacy practices

Cheap habits,
real boundaries.

  • Separate accountsDedicated email/workspace accounts per life domain — shopping, admin, health — so no single account sees everything.
  • Own your memoryIf your agent keeps long-term memory, run that layer locally so the record stays on hardware you own.
